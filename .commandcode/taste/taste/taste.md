# Taste
- Prefers refactors/conversions that remove legacy code outright rather than keeping backward-compatibility shims or leftover dead code ("without backward compat, legacy nor leftovers"); when asked to remove a feature or page, treats "entirely, no leftover" as the bar — every reference goes (views, routes, nav/footer links, feature classes, migrations/seeders, searches, CSS, docs, tests, static-analysis baselines, assets), not just the visible entry point. Confidence: 0.7
- Wants snappy, client-side interactivity (Alpine.js) for UI state instead of waiting on server round-trips ("use alpine for better and snappy interactivity"). Expects derived/live UI (e.g. a summary panel) to update on every keystroke/field change, and treats deferred server-round-trip updates as a defect ("a lot of the form field changes doesnt effect the live brief"). Confidence: 0.75
- Expects seed/reference data to live in database seeders and tables, not only in static JSON resource files ("not cities but seeders"); when data sits in JSON only, treat that as an unfinished gap rather than an acceptable end state. Confidence: 0.55
- Expects the substance of source documents (PDFs/decks) to be extracted and live in the app itself — text, rates, and especially the visuals/images rendered into the HTML pages — rather than the presentation's essence staying locked inside the PDF. The source file stays internal reference only: no visitor-facing PDF, download or deck viewer, since rebuilt HTML is what makes the content searchable, filterable and useful for planning. Confidence: 0.85
- When extracted visuals are missing or not good enough, expects the agent to use the Codex imagegen skills (via Codex CLI) for both generating new images and editing/upscaling existing PDF imagery, keeping a consistent house style; explicitly grants creative latitude to make pages "insanely attractive" rather than settling for plain or default-looking layouts. Confidence: 0.85
- Draws a hard line between real and generated imagery: anything a visitor could identify as a real thing — branded media owners and channels, presenters, studios, programmes, live shows, billboards, venues, events — must use real, attributable imagery sourced from the brand's official site/social/newsroom or licensed photos (with source links and credits), because fake scenes cost trust and integrity; generated images are acceptable only for illustration/mood/concept and must be clearly labelled and kept out of "Inside [brand]" style galleries, instead of being mixed in as if they were actual coverage. Confidence: 0.9
- Everything added must survive `migrate:fresh --seed`: metadata belongs in seeders/seed data (JSON seed files are acceptable when a DB table isn't warranted), with binary assets referenced by path. Confidence: 0.7
- Prefers dedicated Blade views per media owner, per channel, and per deck with hardcoded editorial content, reasoning that media owners and channels are stable and rarely change; dynamic data (rates, search, filters, sorting, calculations) should still come from the database. Confidence: 0.75
- Expects extraction completeness to be demonstrated against the source documents themselves — a source-by-source audit showing every page, price line and visual made it in — rather than inferred from the app working; "nothing from the PDF is missing" must be proven, not assumed. Confidence: 0.65
- Rejects scope reduction for performance/convenience ("dont skip"): if a full pass is too slow, make it faster (parallelize, cache, narrow per-item work) rather than sampling or excluding pages/files; when work genuinely must be deferred, expects a markdown checklist file tracking what remains so nothing is silently dropped. Confidence: 0.7
- Wants slow, multi-part work parallelized with subagents to speed it up ("use subagents where appropriate to speed up"); expects the agent to decompose the job and fan out rather than run everything serially. Confidence: 0.6
- Wants the repository left in a fully committed, pushed, clean state rather than the agent deliberately holding back changes for review ("commit all and push"); don't stop at a working tree with stray lockfile/incidental changes — commit what belongs (adding .gitignore entries for transient runtime files instead of committing them) so nothing is left dangling. Confidence: 0.55
- Expects UI changes to be proven in a real browser (Chrome/CDP or browser MCP) against the live deployed site, not just via PHP tests and grep of static markup; demands screenshot evidence of each page he worked on, checked one by one for failed seeds, broken views, misplaced or missing data, with nothing left unverified or assumed. Confidence: 0.8
